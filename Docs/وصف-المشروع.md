# وصف مشروع نظام إدارة المهام

**Task Management** منصة جامعية لإدارة العمل التعاوني: مساحات عمل، مشاريع، مهام، فريق، إشعارات، وتدقيق إداري.

التطبيق مكوّن من ثلاث طبقات عملاء تتحدث مع **API واحد**:

| الطبقة | التقنية | الموقع في المستودع |
|--------|---------|---------------------|
| الويب | Angular 20 | `Frontend/` |
| الواجهة الخلفية | ASP.NET Core 8 | `Backend/` |
| الموبايل | Expo / React Native | `Mobile/` |

اللغة الأساسية للواجهات **العربية** مع تخطيط **من اليمين إلى اليسار (RTL)**، والسمة البصرية **كحلي + نيلي** مع وضع ليلي/نهاري.

---

## 1. الفكرة ونطاق النظام

النظام ينظّم العمل بهذا التسلسل:

**مستخدم → مساحة عمل (Workspace) → مشروع (Project) → مهمة (Task)**

كل مساحة عمل لها مالك واحد، ومشاريع داخلها، ومهام داخل كل مشروع. الصلاحيات تُحسب داخل المساحة وليس على مستوى النظام كله (باستثناء مسؤول النظام).

ما يغطيه المشروع:

- إنشاء الحسابات وإدارتها من لوحة المسؤول
- إنشاء مساحات العمل وتعيين مالكها
- دعوة الأعضاء وتغيير أدوارهم
- إنشاء المشاريع وتعيين مدير مشروع وأعضاء مشروع
- دورة حياة المهمة: إنشاء، تعيين، تعليق، مرفقات، اعتماديات، تقدم، حالات
- إشعارات فورية وسجل نشاط
- استعادة كلمة المرور بموافقة المسؤول
- تصدير لوحة المسؤول وتدقيق عام على مستوى النظام

ما لا يشمله: تسجيل ذاتي عام للمستخدمين، أو إنشاء مساحة عمل من غير مسؤول النظام.

## 2. الأدوار والصلاحيات

### 2.1 مسؤول النظام (System Admin)

ليس دور مساحة عمل. يُحدَّد بعلم `User.IsSystemAdmin`.

يملك:

- لوحة تحكم إدارية وإحصاءات النظام
- إدارة المستخدمين (إنشاء، تفعيل، تعطيل، عرض الدور والوصف)
- إدارة الأدوار والصلاحيات الثابتة
- إنشاء مساحات العمل وتعيين المالك
- نقل ملكية المساحة
- مراجعة طلبات استعادة كلمة المرور
- سجل التدقيق العام لكل النظام

لا يُدار كمالك/مدير/عضو داخل المساحات من واجهة المستخدم العادية.

### 2.2 أدوار مساحة العمل (ثابتة)

| الدور | الاسم التقني | ماذا يفعل |
|--------|----------------|-----------|
| مالك مساحة عمل | `WorkspaceOwner` | يرى المساحة والفريق والمشاريع والإحصاءات. لا ينشئ المهام ولا يعدّلها ولا يُعيَّن عليها. يدعو مدير مشروع أو عضو. لا يُدعى كمالك؛ الملكية تُنقل عبر المسؤول فقط. |
| مدير مشروع | `ProjectManager` | يدير مشروعه (أو مشاريعه): أعضاء المشروع، المهام، التعيين، التعليقات، المرفقات. |
| عضو | `Member` | يرى المشاريع التي أُضيف إليها، ويعمل على المهام المعيَّن عليها. |

يمكن للمستخدم الواحد أن يملك أدوارًا مختلفة في مساحات مختلفة (مالك هنا، مدير هناك، عضو في ثالثة). في الويب يظهر مبدّل **عرض النظام كـ** لاختيار الشخصية النشطة: مالك / مدير مشروع / عضو.

### 2.3 صلاحيات النظام (`SystemPermissions`)

مرتبطة بالدور داخل المساحة، مع إمكانية تجاوز على مستوى المستخدم (`UserPermissionOverride`):

- مساحة: `workspace.manage`
- أعضاء: `member.invite` ، `member.remove` ، `member.change_role`
- مشاريع: `project.create` ، `project.view` ، `project.update` ، `project.delete`
- مهام: `task.create` ، `task.view` ، `task.details.update` ، `task.status.update` ، `task.delete` ، `task.assign` ، `task.comment` ، `task.attachment.upload`

مسؤول النظام يتجاوز فحص الصلاحيات داخل المساحة.

### 2.4 مستخدم بلا انتماء (Free user)

حساب نشط بلا عضوية في أي مساحة. يرى لوحة محدودة وانتظار دعوة. لا ينشئ مساحة عمل.

## 3. الباك إند (Backend)

### 3.1 البنية

Clean Architecture داخل `Backend/`:

```
TaskManagement.API              ← Controllers, JWT, SignalR, Swagger, ملفات الواجهة الثابتة
TaskManagement.Application      ← خدمات الأعمال، DTOs، الواجهات
TaskManagement.Domain           ← الكيانات، الأدوار، الصلاحيات، التعدادات
TaskManagement.Infrastructure   ← EF Core، Identity، JWT، البريد/التصدير، البذر
TaskManagement.Tests            ← اختبارات الخدمات
```

- إطار العمل: **.NET 8**
- قاعدة البيانات: **SQL Server** (محليًا `localdb` / `TaskManagementDb`)
- الوصول للبيانات: **Entity Framework Core 8** مع ترحيلات
- الهوية: **ASP.NET Core Identity** على كيان `User` (مفتاح رقمي `int`)
- المصادقة: **JWT Bearer** (مدة الجلسة الافتراضية 1440 دقيقة)
- التوثيق: **Swagger**
- الزمن: تحويل التواريخ إلى UTC في JSON

### 3.2 الكيانات الأساسية

| الكيان | الوظيفة |
|--------|---------|
| `User` | الحساب، `IsSystemAdmin`، `IsActive`، `TokenVersion`، آخر دخول |
| `Workspace` | مساحة العمل |
| `WorkspaceMember` | عضوية المستخدم في المساحة مع الدور والحالة |
| `WorkspaceInvitation` | دعوة معلّقة/مقبولة/مرفوضة/ملغاة |
| `Project` | مشروع داخل مساحة، مع `ManagerUserId` اختياري |
| `ProjectMember` | أعضاء المشروع (غير مدير المشروع بالضرورة) |
| `TaskItem` | المهمة: حالة، أولوية، تاريخ استحقاق، نسبة تقدم، ملاحظات تقدم |
| `TaskAssignee` | المعيَّنون على المهمة |
| `TaskComment` | التعليقات |
| `TaskAttachment` | المرفقات |
| `TaskDependency` | اعتماد مهمة على مهمة أخرى في المشروع نفسه |
| `TaskReminder` | تذكيرات الاستحقاق |
| `Notification` | إشعار داخل التطبيق |
| `ActivityLog` | سجل الأحداث |
| `Role` / `Permission` / `RolePermission` | مصفوفة الأدوار والصلاحيات |
| `UserPermissionOverride` | استثناء صلاحية لمستخدم |
| `UserSession` | جلسة الجهاز المرتبطة بالتوكن |
| `PasswordRecoveryRequest` | طلب استعادة كلمة المرور |

الحذف في الغالب **حذف منطقي** (`IsDeleted` / `DeletedAt`) عبر `BaseEntity`.

### 3.3 حالات المهمة والأولوية

حالات المهمة (`TaskItemStatus`):

1. `Todo` — للإنجاز
2. `InProgress` — قيد التنفيذ
3. `PartiallyCompleted` / `InReview` — مكتملة جزئيًا / قيد المراجعة
4. `Done` — مكتملة
5. `Cancelled` — ملغاة

الأولوية: منخفضة، متوسطة، عالية، حرجة.

### 3.4 واجهات الـ API الرئيسية

| المتحكم | المجال |
|---------|--------|
| `AuthController` | دخول، ملف شخصي، تسجيل (للمسؤول)، استعادة كلمة المرور |
| `AdminController` | لوحة المسؤول، المستخدمون، حالة الحساب |
| `WorkspacesController` | المساحات، التعديل، الحذف، نقل الملكية |
| `WorkspaceMembersController` | الأعضاء، الأدوار، المرشحون |
| `WorkspaceInvitationsController` | دعوات المساحة وقبولها/رفضها |
| `ProjectsController` | المشاريع وأعضاء المشروع |
| `TasksController` | المهام والتقدم والحالات |
| `TaskAssigneesController` | تعيين المهام |
| `TaskCommentsController` | التعليقات |
| `TaskAttachmentsController` | المرفقات |
| `TaskDependenciesController` | الاعتماديات |
| `NotificationsController` | الإشعارات اليدوية والواردة |
| `ActivityLogsController` | نشاط المساحة |
| `AdminActivityLogsController` | التدقيق العام |
| `RolesPermissionsController` | الأدوار والصلاحيات |
| `UserPermissionsController` | تجاوزات صلاحيات المستخدم |
| `PasswordRecoveryAdminController` | موافقة/رفض طلبات الاستعادة |

المنافذ المحلية:

- HTTPS: `https://localhost:7047`
- HTTP: `http://localhost:5056`

الويب يتصل بـ `https://localhost:7047`. الموبايل افتراضيًا `http://localhost:5056`.

### 3.5 الأمان والجلسات

- الدخول بالبريد وكلمة المرور مع اختياري `DeviceId` / `DeviceName`
- التوكن يحمل هوية المستخدم وإصدار `TokenVersion`
- تعطيل الحساب يزيد `TokenVersion` فيُبطل كل الجلسات الحالية
- CORS مسموح لعملاء الواجهة
- SignalR على `/hubs/notifications` ويتطلب JWT؛ كل مستخدم في مجموعة `notification-user-{id}`

### 3.6 الخدمات الخلفية المستمرة

`TaskReminderBackgroundService` يعمل كل دقيقة ويرسل تذكيرات الاستحقاق كإشعارات.

في الإنتاج يمكن تقديم بناء Angular من `wwwroot` مع `MapFallback` لمسارات الـ SPA، مع استثناء `/api` و `/hubs` و `/swagger`.

## 4. الفرونت إند (Angular)

### 4.1 التقنية

- Angular **20** (standalone components، تدفق `@if` / `@for`)
- التوجيه والحراسة: `authGuard` ، `adminGuard`
- اعتراض HTTP لإرفاق JWT ومعالجة 401
- SignalR عبر `@microsoft/signalr`
- الأنماط: SCSS، RTL، دون Chart.js (الرسوم عبر CSS/SVG)

التشغيل: `Frontend/` ثم `ng serve` على `http://localhost:4200`.

### 4.2 الصفحات

| المسار | الصفحة | من يراها |
|--------|--------|----------|
| `/login` | تسجيل الدخول واستعادة كلمة المرور | عام |
| `/dashboard` | لوحة حسب الدور النشط | مستخدم مسجّل |
| `/account` | الحساب الشخصي | الجميع |
| `/workspaces` | إدارة المساحات | المسؤول (إنشاء/نقل ملكية) وصاحب الدور المناسب |
| `/projects` و `/workspaces/:id/projects` | المشاريع | مالك / مدير / عضو حسب الرؤية |
| `/tasks` و `.../projects/:id/tasks` | المهام | مدير مشروع وعضو (المالك لا يدير المهام) |
| `/team` | أعضاء المساحة والدعوات | مالك ومدير بحسب الصلاحية |
| `/activity` | سجل النشاط / التدقيق العام للمسؤول | الجميع مع نطاق مختلف |
| `/notifications` | الإشعارات | الجميع |
| `/admin` | لوحة المسؤول | System Admin |
| `/admin/users` | إدارة المستخدمين | System Admin |
| `/admin/roles-permissions` | الأدوار والصلاحيات | System Admin |
| `/admin/password-recovery` | طلبات استعادة كلمة المرور | System Admin |

### 4.3 تجربة الدور في الويب

- الشريط الجانبي يتغير حسب المسؤول أو الشخصية النشطة.
- مبدّل **عرض النظام كـ** يظهر إذا كان للمستخدم أكثر من دور عبر المساحات.
- لوحة المالك: اسم المساحة ورسوم المهام/الفريق دون صناديق مساحات زائدة.
- لوحة مدير المشروع: المشروع الذي يديره والرسوم.
- لوحة العضو: المساحة والمشاريع التي ينتمي إليها، ومهامه فقط.
- مالك المساحة لا يدخل إدارة المهام التشغيلية؛ يتابع عبر لوحة المعلومات والفريق.

### 4.4 إدارة المستخدمين (المسؤول)

جدول الحسابات يعرض:

- **ID**
- المستخدم (الاسم والبريد)
- **الدور**: عضو / مدير مشروع / مالك مساحة عمل / مدير النظام
- **وصف المستخدم**: المساحة و/أو المشروع المرتبط بالدور
- الحالة وآخر دخول وإجراءات التفاصيل/التعطيل

## 5. تطبيق الموبايل (Expo)

المجلد `Mobile/` — تطبيق عربي RTL على **Expo 57** و **React Native 0.86** و **React 19**.

### 5.1 البنية

- `src/api` عميل HTTP وخدمات مطابقة للـ API
- `src/access/AccessProvider` حالة الدخول والأدوار والقوائم الظاهرة
- `src/navigation` تكديس شاشات + تبويبات سفلية
- `src/screens` الشاشات
- `src/storage` حفظ الجلسة (SecureStore)
- `src/theme` الوضع الليلي/النهاري وخط IBM Plex Sans Arabic

العنوان الافتراضي للـ API: `http://localhost:5056` عبر `EXPO_PUBLIC_API_BASE_URL`.

### 5.2 التبويبات والشاشات

التبويبات: الرئيسية، المشاريع (إن وُجدت صلاحية)، المهام (إن وُجدت)، الإشعارات، المزيد.

من التكديس: تفاصيل المشروع وأعضاؤه، المهام وإنشاؤها وتفاصيلها، الفريق، النشاط، إنشاء مساحة (للمسؤول)، المستخدمون (للمسؤول)، الحساب.

الموبايل يعيد استخدام قواعد الوصول نفسها (مسؤول / مالك / مدير / عضو) دون مبدّل شخصية الويب؛ القوائم تُشتق من المساحات والأدوار الفعلية.

## 6. التكامل بين الطبقات

```
[ Angular :4200 ] ──HTTPS──┐
                           ├──► [ ASP.NET API :7047 / :5056 ] ──► [ SQL Server ]
[ Expo Mobile ] ──HTTP─────┘              │
                                          └── SignalR /hubs/notifications
```

- كل عمليات الكتابة تمر بالـ API وتُسجَّل في `ActivityLog` عند الأحداث المهمة.
- الإشعارات تُحفظ في قاعدة البيانات وتُدفع لحظيًا عبر SignalR إن كان العميل متصلًا.
- بناء الويب يمكن نسخه إلى `Backend/TaskManagement.API/wwwroot` ليُقدَّم مع الـ API في النشر.

---

## 7. التشغيل المحلي المعتاد

1. تشغيل الـ API من Visual Studio (الملف الشخصي HTTPS).
2. تطبيق ترحيلات قاعدة البيانات إن لزم (`dotnet ef database update`).
3. تشغيل الواجهة: داخل `Frontend/` الأمر `ng serve`.
4. الموبايل اختياري: داخل `Mobile/` الأمر `expo start`، مع ضبط عنوان الـ API لجهازك.

حساب مسؤول النظام يُبذر عند تهيئة قاعدة البيانات. إنشاء بقية الحسابات يتم من واجهة المسؤول فقط.
